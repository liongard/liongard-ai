## 7. QA rules

Run a QA pass after data collection and before rendering. Canonical categories (full detail in the knowledge document "Reference: QA Retry Pattern"):

- **Category 1 — Transient nulls (retry)** - A metric or asset query that returns `null` may be: - A genuine absence ("there is no value") - A transient miss (inspector mid-cycle, API throttle, sync lag)
- **Category 2 — Stale inspector (flag, don't retry)** - A system / asset record with `lastSeen` older than `qa.flag_inspector_lastseen_threshold_days` (default 7) is reporting stale data. Don't retry — the data won't change without the inspector running.
- **Category 3 — Count divergence (flag, don't pick a winner)** - When two tools answer the same question differently — for example, `liongard_identity COUNT mfaStatus="NO"` returns 12, but the per-inspector M365 metric `683` (Admin MFA Disabled Count) returns 8 — surface **both values** and let the user decide. Do not silently pick one.
- **Category 4 — Known proposed-metric gaps (flag, list)** - Recipes that depend on metrics marked `[PROPOSED]` (not yet in the Liongard library — see the recipe catalog) should explicitly list which fields are not directly available, with the workaround the recipe used and the manual-check action.
- **Category 5 — Single-source data quality flag** - When data for an asset comes from only one inspector (e.g., a device with `inspectors[]` containing only `active-directory-inspector`), security fields like `antivirus`, `edr`, BitLocker status will be `null` — the inspector that would populate them hasn't run.

Always append a "Manual Verification Needed" section listing every item flagged above.

## 4. Report

Sections, in order: Executive Summary; Firewall Identity & Firmware; Interface & DNS Configuration; Subscription Services (TSS / GAV / IPS / etc.); Firewall Policies; BOVPN & Mobile VPN; Local User & Admin Audit; Recommended Actions; Data Gaps & Coverage Notes.

Thresholds: inspector_lastseen_days_max=1; license_expiration_warn_days=60; firmware_age_months_max=12; open_rdp_to_internet_allowed=False; wan_management_exposure_allowed=False; default_local_users_max=1.

Report each metric's actual value. Show "No data" for empty values; never mark a control passing without a supporting value. A "No data" row is a coverage gap only if the control matters and no other row covers it.

Coverage table: metrics fetched / required, with data / no data counts. Internal audience: add a verification log, one row per call (seq, metricId, result shape, status).
