Partner setup guide · Microsoft Copilot Studio

Set up the Liongard MSP Assistant

Upload the three Liongard recipe skills, connect your Liongard tenant, test the agent, and publish it to Microsoft Teams or Microsoft 365 Copilot.

No GitHub account or GitHub Copilot license is required. “GitHub Copilot harness” is Microsoft’s name for the newer agent runtime inside Copilot Studio. All setup below happens in Microsoft Copilot Studio.

What Liongard sends you

Download and unzip the outer release package. It should contain:

Liongard-Copilot-Studio/
├── START-HERE.html                   Open this first (this guide)
├── skills/
│   ├── liongard-single-system.zip    Upload as a Skill (one vendor at a time)
│   ├── liongard-rollups.zip          Upload as a Skill (all systems of one type)
│   └── liongard-environment.zip      Upload as a Skill (onboarding, QBR, MFA audit, compliance)
├── agent-instructions.txt            Customize the MSP profile, then paste into the agent
└── manifest.json                     Release version and checksums

The library ships as three skills because Copilot Studio rejects very large skills. Upload all three; a report in one skill can use recipes from another (for example, onboarding runs the single-system recipe for each vendor you have).

Keep credentials separate. The release package must never contain your Liongard access key, customer data, reports, or Microsoft credentials.

Before you begin

  • A Copilot Studio standalone license and permission to create agents.
  • Copilot Credits allocated to the Power Platform environment, or pay-as-you-go enabled.
  • Your Liongard MCP endpoint and a Liongard access key supplied through an approved secure channel.
  • Microsoft administrator approval for MCP tools, the selected model, and publishing to Teams or Microsoft 365.

Set up the agent

  1. Create the agent

    Open Microsoft Copilot Studio, select the correct Power Platform environment, and create a new Agent.

    Name it Liongard MSP Assistant. Use the current agent experience that displays a Build tab with Skills and Tools. Do not choose a classic or “other ways to build” agent.

    Keep the agent free of knowledge sources. Under Knowledge, remove everything, including Search all websites if it was added by default. Skills cannot be combined with uploaded knowledge files in the current preview, and web results must never mix with customer data. Do not add connected agents.

  2. Set the model and instructions

    Select a model that follows long, multi-step instructions. Tested for this release:

    ModelResult
    GPT 6 SolRecommended where Anthropic models are not permitted (for example CMMC environments). Completed single-system, MFA audit and onboarding tests.
    Claude Opus 5.5Recommended where permitted; Liongard’s reference model for recipe testing.
    GPT 5.6 ReasoningNot supported: stalled without calling tools.
    GPT 5.6 TerraNot supported: skipped recipe steps.

    Open agent-instructions.txt, fill in the MSP profile block at the top, then paste the complete file into the agent’s Instructions field. Values you set there override Liongard’s default profile bundled in the skills.

    Profile values: MSP display name, primary color, default audience, default output format, preferred technology stack, and reporting thresholds.

  3. Upload the three Liongard skills

    Build → Skills → Add skill → Upload a skill

    Upload each file in skills/ one at a time: liongard-single-system.zip, liongard-rollups.zip and liongard-environment.zip. Do not upload the outer release ZIP and do not unpack the skill ZIPs.

    After each upload, check the Skills list. Copilot Studio can show “saved” even when it has dropped a skill. All three must appear: liongard-single-system, liongard-rollups, liongard-environment. If one is missing, upload it again.

  4. Connect the Liongard MCP server

    Build → Tools → Add → Model Context Protocol

    FieldValue
    NameLiongard
    DescriptionRead-only access to live Liongard environments, inspectors, inventory, metrics, alerts, detections, and timelines.
    Server URLhttps://<your-instance>.app.liongard.com/api/mcp
    HeaderAuthorization
    ValueBearer <accessKeyId>:<accessKeySecret>

    Authorize the connection and save it. Enable the required liongard_* tools. Do not enter a Liongard UI password and do not paste the access key into agent instructions, knowledge, or the Skill.

  5. Verify the connection

    Open Preview, start a fresh conversation, and enter:

    Using Liongard, count the environments I can access.

    Open the activity trace. Confirm that the agent called liongard_environment with the COUNT operation and returned a result without an authentication error.

  6. Try a report

    In a fresh conversation, ask for an assessment of a vendor deployed in one of your environments, for example:

    Run the <vendor> assessment for <environment>. Markdown, internal audience.

    The activity trace should show a Liongard skill being used, and the report should end with a coverage table and “Manual Verification Needed”. Every metric in the coverage table has a value, “No data” or an error—none silently missing.

    Large reports may ask you to continue. An onboarding assessment can need several hundred Liongard calls. Copilot Studio limits how much one reply can do, so the agent may stop with “Reply continue to run the remaining steps.” Reply continue until the final report appears. Single-system reports normally finish in one reply.

  7. Publish and share

    Select Publish. Add the Microsoft Teams or Microsoft 365 Copilot channel, then follow your organization’s administrator-approval process before making the agent broadly available.

Setup is complete when: all three skills are loaded, the Liongard MCP connection succeeds, a test report completes with full coverage, and the published agent is limited to authorized users.

Updating the Liongard recipes

  1. Download the new Liongard release and verify its version in manifest.json.
  2. In the agent’s Skills list, remove each Liongard skill, then upload the new liongard-single-system.zip, liongard-rollups.zip and liongard-environment.zip.
  3. Confirm all three appear in the Skills list.
  4. Keep the existing MCP connection and MSP profile unless the release notes say otherwise.
  5. Republish, then repeat the connection check and a test report in fresh conversations.

Quick troubleshooting

ProblemWhat to check
No Skills optionThe agent was likely created with the older standard harness, or Skills are not enabled for this environment. Create an agent in the current experience or contact the Microsoft administrator.
Skill missing after uploadCopilot Studio sometimes drops an upload without an error. Upload that skill ZIP again. Upload the inner files from skills/, not the outer release, and confirm the checksum in manifest.json.
Agent searches knowledge or the webRemove every knowledge source, including Search all websites; the skills hold the recipes.
Report stops before the endReply continue. If it stops again without progress, start a fresh conversation and run the report again.
401 / unauthorizedConfirm the endpoint ends in /api/mcp and the authorization value contains both access-key parts separated by one colon.
Tools do not appearEdit or refresh the MCP connection so Copilot Studio repeats the MCP handshake and tool discovery.
Metrics were skippedStart a fresh conversation, inspect the activity trace and coverage table, and record the model and missing sequence IDs before contacting support.
